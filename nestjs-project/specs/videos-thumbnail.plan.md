# GET /videos/:id/thumbnail Test Plan

## Application Overview

Returns a presigned GET URL for the thumbnail generated by the worker, with the same access rule as the video: the owner once the thumbnail exists, everyone else only for a `ready` video. While `thumbnail_key` is null the route answers a conflict.

## Test Scenarios

### 1. Thumbnail URL

**Setup:** `beforeAll` bootstraps `AppModule` with the `main.ts` global config (`ValidationPipe`, `DomainExceptionFilter`, `ValidationExceptionFilter`). `S3_PUBLIC_ENDPOINT` is set to the internal storage address (`http://storage:9000`), because a URL signed for the host-published address is unreachable from inside the `nestjs-api` container (Hipótese, per SI-03.4). `beforeEach` runs `cleanAllTables` and clears the throttler storage. Real database and real storage. Two confirmed users with channels and tokens; a `ready` video with a JPEG object at its `thumbnail_key`, a `ready` video with `thumbnail_key` null and a `processing` video are inserted for the first user's channel.
